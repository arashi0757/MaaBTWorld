## 4. 已发现的准备问题与待验证项

1. 图标缺失：interface.json 的 icon 为 logo.ico，仓库中没有该文件。后续需要提供真实图标或调整图标声明；本轮不补造图标。
2. 显示基准待核对：控制器短边为 720，许多识别区域采用 1280×720 范围；账号任务说明要求 900×1600、320 DPI。需核对实际截屏、方向、缩放及登录 SDK 页面，不按手机标称分辨率批量改坐标。
3. 版本选择待核对：官服与台服节点目前都填写 com.netease.sjzw，选项仅启用选中节点，未明确禁用另一节点。第一版限定安卓官服，不能把台服视为已支持。
4. 账号参数待核对：菜单 override 使用顶层 expected，而对应节点采用 recognition.param.expected。需要依据固定引擎版本验证覆盖行为，不能仅凭静态 JSON 解析认定输入生效。
5. 失败恢复待验证：部分流程会回到自身或依赖 JumpBack；需要规定总时限、停止入口、失败截图和日志。文件引用完整不等于能够避免长时间循环。
6. Python Agent 保留：当前 interface 声明 uv run python agent/bootstrap.py；Agent 启动时注册通用动作/识别，即使 Pipeline 暂未调用，运行端仍可能尝试启动它。
7. 版本漂移：maafw 依赖范围为 >=5.0，项目运行库和工具存在 stable/latest 配置；requirements.txt 当前列出 maafw 5.12.2。后续应固定并记录桌面、Android 引擎和协议版本，不能把 Python 包版本当作所有运行库已锁定。
8. 自动检查覆盖范围：Check 工作流监听 pull_request 和 main/master 推送；直接推送本开发分支不会触发该检查。若以后希望在 GitHub 云端检查，应另行配置开发分支检查或手动检查入口。
9. 工作流依赖有效性未验证：未运行 Actions，也未逐项确认所引用 action 版本能成功拉取；不把“已有工作流文件”等同于“检查已通过”。

## 5. Windows 与 Android 路线

### Windows 调试准备

仓库配置要求 Node 24、pnpm 11.5.1、Python 3.13（>=3.13,<3.14）和 uv。VS Code 已有 Maa Support / Python Agent 调试相关配置。实际桌面运行库需要另外准备，并记录版本。

现在不安装这些工具。准备运行测试时，再逐项检查电脑已有环境，缺什么补什么，避免重复安装。

Windows 调试工具需要在电脑上运行并取得测试资源；仅通过 GitHub 网页不能操作本地手机。到设备测试阶段，再决定使用小米14 USB ADB 或模拟器。优先验证与目标手机一致的安卓官服环境。

### Android 候选方案

MaaFwApp 可作为候选外壳，最终选型尚需兼容性验证。

官方文档：

- https://github.com/Aliothmoon/MaaFwApp
- https://github.com/Aliothmoon/MaaFwApp/blob/main/INTEGRATION.md

截至本轮核对，MaaFwApp 支持 PI V2、Shizuku/root 与本机 native controller；配置中的 Adb 控制器可被接入，不需要为本机运行随意新增一种控制器类型。

当前 MaaBTWorld 发布脚本只处理 Windows/Linux/macOS，不能直接产出 Android APK。Android 需要独立打包配方、arm64-v8a MaaFramework 运行库、应用标识、图标、签名与日志方案；若保留 Agent，还需对应 Android Python/Agent 运行时。桌面 uv 启动声明不能直接作为手机运行环境。

MaaFwApp 当前资源在构建期放入 APK，资源变更后需重新出包。其文档要求 JDK 17、Android SDK、Python 3。后台虚拟屏与 HyperOS 保活、权限、截屏和触控均为待真机验证项。先前台验证，再研究后台；不承诺小米14直接兼容。
