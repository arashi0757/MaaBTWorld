日期：2026-11-03。状态：配置已修改，未运行游戏，未执行完整项目检查或构建。

## 本次改动

- tasks/StartUp.json 的两个菜单入口改用新文件 official_startup.json 中的官服启动节点。
- 只保留安卓官服菜单选项，原台服与旧启动/切号文件仍保留，但新入口不引用它们。
- 默认不切换账号。指定账号登录开关明确默认 No；需要时才展开账号输入。
- 账号识别内容限制为1至3位英文字母或数字，默认空。Client 需按 PI verify 校验；输入失败不得启动指定账号任务。
- 账号覆盖使用 recognition.type/param.expected，并保留原 roi，避免混用顶层 expected；任务日志提示不插入账号输入。
- 不带输入覆盖时，账号识别节点使用 ^$，避免继续匹配原作者示例中的89。该措施不替代 Client 输入校验，尤其不能允许空输入覆盖成空正则。
- 官服启动分支先尝试识别主页，已进入主页时可以结束启动链。
- 删除“点击开始旅程”的 on_error 自我重试；删除公共退出处理中的错误转空节点路径。
- 新入口包含37个独立节点，原识别模板、区域、点击、滑动位置和动作保持原样。
- 资源收集入口和 Python Agent 未修改。

## 次数与等待

按 MaaFramework 协议，timeout 限制的是当前节点等待 next 列表的时间，不是整项任务的总运行时间。

- 常规 next 等待设为20秒，官服启动和指定账号启动节点的 next 等待为60秒。
- 启动、重启和更新重登节点最多命中2次。
- 下载/连接提示和等待节点最多命中24次；其余新节点最多命中12次。
- 每个新节点均有有限 max_hit；没有配置 timeout=-1。
- 上限耗尽后节点会被引擎跳过；若剩余候选均无法匹配，按引擎超时/失败结束。未新增假成功节点。
- 这不是整项任务“60秒必定结束”的保证。累计时长、JumpBack、命中计数重置和 Client 失败显示仍需引擎及真机验证。
- 当前没有新增验证码识别或自动确认授权功能；遇到这些界面需手动处理，任务可能在处理前超时。

## 静态检查

1. 新 JSON 可解析，37个新节点的 next/on_error 引用均指向本文件节点。
2. 两个菜单入口、option 引用和 option override 目标均可解析。
3. 新链不引用台服、原切号/启动节点或资源消耗节点。
4. 每个新节点有有限命中次数；存在 next 的节点具有有限正 timeout。
5. 复用动作逐项与原文件比较一致，识别区域/模板保留；账号节点仅更换 expected。
6. 验证8组输入：空值、4位输入、正则符号、空格、中文被拒；1至3位英文字母/数字通过。
7. 登录失败不再直接回到“点击开始旅程”，公共退出失败不再转空成功节点。

上述检查不包含完整 JSON Schema、格式检查、MaaFramework 资源加载、Agent 连接或真实 OCR/点击验证。原始文件中的 ^$ 策略与 Client verify 行为也必须实测，不能把静态检查当作账号选择已正确。
